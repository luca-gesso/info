C++ · Lezione 1

Com'è fatto un programma C++

Ogni programma che scriverai in verifica ha questa struttura. Impara a memoria le prime due righe e il main.

Le cose da sapere

  • cout << manda verso lo schermo. Puoi concatenare più pezzi: cout << "x = " << x << endl;
  • cin >> prende dalla tastiera e mette nella variabile. Le frecce indicano la direzione dei dati.
  • Ogni istruzione finisce con ;. Le graffe { } raggruppano le istruzioni in un blocco.
  • // inizia un commento. La prof chiede di commentare: una riga sopra ogni funzione che dice cosa fa basta e avanza.
  • Una variabile va dichiarata (tipo + nome) prima di usarla.
Ricorda la differenza con JavaIn Java non esistono cout e <<: si usa System.out.println("x = " + x);. Lo vediamo nella lezione 8.

La divisione: la trappola numero 1

Se entrambi i numeri sono interi, la divisione è intera: la parte decimale viene buttata (non arrotondata).

Il resto % serve a un sacco di cose

  • n % 2 == 0 → n è pari
  • n % 10 → ultima cifra di n (352 % 10 = 2)
  • n / 10 → n senza l'ultima cifra (352 / 10 = 35)
  • n % k == 0 → n è multiplo di k

Perché la costante?

Se domani i punti diventano 10, cambi solo const int N = 10;: cicli, media e dichiarazioni si aggiornano da soli. La prof lo scrive nei requisiti («le dimensioni sono gestite con una costante»). Se scrivi 8 sparso nel codice perdi punti anche se il programma funziona.

Uscire dall'arrayIn C++ nessuno ti avvisa: v[8] legge memoria a caso (valori «spazzatura») o fa crashare il programma. In Java invece il programma si ferma con ArrayIndexOutOfBoundsException.

Funzioni

Una funzione è un pezzo di programma con un nome, che puoi richiamare. In verifica la prof vuole una funzione per ogni voce del menu, richiamata dal main.

Restituisce o stampa?

La funzione…TipoEsempi

Il trucco per scrivere poco: le funzioni del menu (void) richiamano le funzioni di calcolo. Così media la scrivi una volta e la usi nella voce 3 e nella voce 4.

Passaggio per valore e per riferimento

  • Senza & → la funzione riceve una copia: le modifiche spariscono alla fine.
  • Con & → la funzione lavora sulla variabile vera del main.
  • Gli array fanno eccezione: non vengono copiati, si passa il loro indirizzo. Per questo inserisci(double v[]) riempie davvero l'array del main senza &. Nelle [] del parametro non serve scrivere la dimensione.
Dove le scrivo?Sopra il main. Il compilatore legge dall'alto: se usi una funzione prima di averla scritta ottieni 'media' was not declared in this scope.
C++ · Lezione 5

Cicli e menu

CicloQuando si usa
for (int i = 0; i < N; i++)sai quante volte: scorrere un array, una stringa
while (condizione) { … }controlla prima: può non eseguire mai
do { … } while (condizione);controlla dopo: esegue almeno una volta → perfetto per il menu

Lo scheletro del menu (impara questo a memoria)

  • Il do-while mostra il menu subito, poi controlla se ripetere. Con un while normale scelta al primo controllo non avrebbe un valore.
  • Lo switch salta al case col valore di scelta.
  • break esce dallo switch. Se lo dimentichi, continua a eseguire anche i case sotto (fall-through).
  • default cattura tutto il resto (es. l'utente scrive 9).
  • Gli array si dichiarano nel main, fuori dal do: altrimenti verrebbero ricreati vuoti a ogni giro.
Consiglio da verificaScrivi subito questo scheletro con tutti i case che chiamano funzioni ancora vuote, e compila. Poi riempi le funzioni una alla volta, compilando ogni volta. Così non ti ritrovi con 40 errori alla fine.

Le 4 trappole delle stringhe

  1. char vs String: 'a' (apici singoli) è un carattere, "a" è una stringa. charAt dà un char, quindi c == 'a'.
  2. Le stringhe non cambiano mai: frase.toLowerCase(); da solo non fa niente. Serve frase = frase.toLowerCase();
  3. Confronto: s1.equals(s2), mai s1 == s2 (confronta se sono lo stesso oggetto, non il contenuto). Per i char invece == va benissimo.
  4. length: stringa s.length() con parentesi, array v.length senza.

Ricorsione

Una funzione è ricorsiva quando richiama sé stessa su un problema più piccolo. Ha sempre due parti:

  • Caso base: quando fermarsi, restituendo un valore senza richiamarsi.
  • Passo ricorsivo: richiamarsi con un valore più vicino al caso base (di solito n - 1 o n / 10).

Come tracciarla: la «scala»

Scendi scrivendo ogni chiamata finché arrivi al caso base, poi risali calcolando.

misterioso(4) = 4 * misterioso(3)
              = 4 * 3 * misterioso(2)
              = 4 * 3 * 2 * misterioso(1)     ← caso base: vale 1
              = 4 * 3 * 2 * 1
              = 24

In verifica scrivi proprio questa scala come «motivazione»: è quello che la prof vuole vedere.

Le ricorsive che escono più spesso

CodiceCalcolaEsempio
if (n <= 1) return 1;
return n * f(n-1);		fattorialef(4) = 24
if (n == 0) return 0;
return n + f(n-1);		somma 1…nf(5) = 15
if (e == 0) return 1;
return b * f(b, e-1);		potenza bef(2,3) = 8
if (n < 10) return n;
return n%10 + f(n/10);		somma delle cifref(352) = 10
if (n < 10) return 1;
return 1 + f(n/10);		numero di cifref(4071) = 4

Trappola: stampa prima o dopo la chiamata?

In b la stampa avviene «al ritorno», quando le chiamate più piccole hanno già finito: quindi l'ordine è al contrario.

Senza caso baseLa funzione si richiama all'infinito: ogni chiamata occupa memoria nello stack finché questa finisce → stack overflow, il programma va in crash.
Teoria · Lezione 12

Come risolvere «cosa stampa?»

  1. Controlla prima che compili. Graffe chiuse? << in Java? Se c'è un errore, scrivilo: è parte della risposta.
  2. Fai la tabella di traccia: una colonna per ogni variabile, una riga per ogni giro.
  3. Guarda dove sta la stampa: dentro il ciclo stampa a ogni giro, fuori una volta sola alla fine.
  4. Scrivi l'output esatto, con spazi e a capo.

Esempio: il programma della tua verifica

ii % 2 == 0?operazionesomma
––inizio0
1nosomma −= 1−1
2sìsomma += 21
3nosomma −= 3−2
4sìsomma += 42
5nosomma −= 5−3

Output: somma finale: -3. Motivazione: i pari (2+4 = 6) vengono sommati e i dispari (1+3+5 = 9) sottratti: 6 − 9 = −3.

Nel testo che avevi tuLa println era indentata dentro il for e mancava una graffa: scritto così non compila. Se la println fosse dentro il ciclo, stamperebbe 5 righe: −1, 1, −2, 2, −3. Scrivere entrambe le osservazioni fa una bella figura.

Le trappole preferite dai prof

  • i <= 5 o i < 5? Conta bene quanti giri.
  • i += 2, i -= 3: il passo non è sempre 1.
  • Il while controlla prima di moltiplicare: il valore finale supera il limite.
  • Divisione tra int: 5 / 2 = 2.
  • Java: "x" + 1 + 2 = "x12".
  • Switch senza break: esegue i case successivi.

Cosa stampa?
